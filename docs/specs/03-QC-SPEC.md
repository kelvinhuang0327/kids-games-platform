# 幼兒網頁遊戲 - QC 測試規格 (QC Spec)

**文件版本**: v1.0
**更新日期**: 2025-10-27
**狀態**: Draft

---

## 1. 測試概述 (Testing Overview)

### 1.1 文件目的
本文件為「幼兒網頁遊戲平台」的品質控制與測試規格書，定義：
- 測試範圍與策略
- 測試項目與案例
- 測試工具與流程
- 品質標準與驗收條件

### 1.2 測試範圍
**涵蓋範圍**:
- UI/UX 互動測試
- 遊戲邏輯與規則驗證
- 音效與視覺效果測試
- 家長控制功能測試
- 安全與隱私機制驗證
- 響應式設計與跨裝置相容性
- 性能與可用性測試
- 無障礙功能驗證

**不涵蓋範圍**:
- 後端 API 測試 (本專案為純前端應用)
- 負載測試 (無伺服器負載)
- 安全滲透測試 (需專業資安團隊)

### 1.3 測試類型
| 測試類型 | 目的 | 執行時機 | 負責人 |
|----------|------|----------|--------|
| **單元測試** | 驗證個別函式/組件正確性 | 開發期間、每次提交 | 開發工程師 |
| **整合測試** | 驗證模組間協作 | 功能開發完成後 | 開發工程師 |
| **E2E 測試** | 驗證完整使用者流程 | Sprint 結束前 | QA 工程師 |
| **手動測試** | 驗證使用體驗與視覺品質 | Release 前 | QA 工程師 |
| **回歸測試** | 確保修改未破壞既有功能 | 每次部署前 | 自動化 CI |
| **驗收測試** | 確認符合需求規格 | Release 前 | 產品經理 + QA |

import { test, expect } from '@playwright/test'

test.describe('Complete User Flow', () => {
  test('user can select age group, play game, and complete', async ({ page }) => {
    // 1. 訪問首頁
    await page.goto('/')
    await expect(page).toHaveTitle(/幼兒遊戲樂園/)

    // 2. 選擇年齡組
    await page.click('text=4-6 歲')
    await expect(page).toHaveURL(/\/hall\/4-6/)

    // 3. 選擇拼圖遊戲
    await page.click('text=拼圖')
    await expect(page.locator('.puzzle-game')).toBeVisible()

    // 4. 完成拼圖 (簡化示範)
    const pieces = page.locator('[data-testid="puzzle-piece"]')
    const count = await pieces.count()
    for (let i = 0; i < count; i++) {
      await pieces.nth(i).dragTo(page.locator('[data-testid="puzzle-board"]'))
    }

    // 5. 驗證完成畫面
    await expect(page.locator('text=太棒了')).toBeVisible({ timeout: 10000 })

    // 6. 返回大廳
    await page.click('text=換遊戲')
    await expect(page).toHaveURL(/\/hall\/4-6/)
  })

  test('parental control access requires verification', async ({ page }) => {
    await page.goto('/')
    await page.click('text=家長')

    // 驗證畫面出現
    await expect(page.locator('text=簡單數學題')).toBeVisible()

    // 錯誤答案
    await page.fill('input[type="number"]', '999')
    await page.click('text=確認')
    await expect(page.locator('text=答案不正確')).toBeVisible()

    // 正確答案 (假設答案是 8)
    await page.fill('input[type="number"]', '8')
    await page.click('text=確認')
    await expect(page).toHaveURL(/\/parental/)
  })
})

### 4.3 缺陷管理

#### 4.3.1 嚴重性分級
| 級別 | 定義 | 範例 | 處理時效 |
|------|------|------|----------|
| **P0 - Critical** | 阻擋核心功能，無替代方案 | 遊戲無法啟動、資料遺失 | 立即修復 |
| **P1 - High** | 影響重要功能，有替代方案 | 音效無法播放、進度未保存 | 24小時內 |
| **P2 - Medium** | 影響次要功能或體驗 | 動畫不流暢、樣式錯位 | 1週內 |
| **P3 - Low** | 輕微問題，不影響使用 | 文字錯字、小視覺瑕疵 | 下個版本 |

#### 4.3.2 缺陷追蹤流程
1. **發現** → QA 工程師記錄於 Issue Tracker
2. **評估** → 技術負責人評估嚴重性與優先級
3. **分派** → 指派給開發工程師
4. **修復** → 開發工程師修復並提交 PR
5. **驗證** → QA 工程師驗證修復
6. **關閉** → 確認修復後關閉 Issue

#### 4.3.3 回歸測試策略
**觸發時機**:
- 每次 PR 合併前
- 每日自動化測試 (nightly build)
- Release 前完整回歸

**測試範圍**:
- 自動化回歸套件 (冒煙測試)
- 與修改相關的功能區域
- Release 前: 完整手動回歸

### 6.3 常見測試陷阱與解決方案

| 問題 | 解決方案 |
|------|----------|
| **非同步測試失敗** | 使用 `waitFor` 等待狀態更新 |
| **音效測試不穩定** | Mock 音效模組，測試函式調用而非實際播放 |
| **E2E 測試 Timeout** | 增加 timeout、確保測試環境穩定、添加重試機制 |
| **覆蓋率不足** | 識別未覆蓋區域、補充邊界條件測試 |
| **CI 環境測試失敗** | 使用 headless 模式、確保環境一致性、檢查非同步時序 |

### 6.4 測試最佳實踐

1. **AAA 模式**: Arrange (準備) → Act (執行) → Assert (斷言)
2. **單一職責**: 每個測試只測一個功能點
3. **獨立性**: 測試間不依賴、不共享狀態
4. **可讀性**: 測試名稱清晰描述測試內容
5. **維護性**: 使用 Test Fixtures 與 Helpers 減少重複
